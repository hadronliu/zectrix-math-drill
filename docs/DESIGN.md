# 设计决策（DESIGN）

本文档记录影响实现的关键决策，供贡献者快速理解代码形态。

## 1. 模块分层（显示适配缝）

逻辑层（question/parser/session/store/app）**不依赖设备与 SDK**，只通过
`display::DisplayIntent`（CLI 文本）或 `render::Renderer`（400×300 PNG）表达显示意图。
设备接入被 feature 门控（`device`），核心仓库可独立构建与测试。

## 2. 中文数字解析是全函数

`parser::parse_answer` 对**任何输入都不 panic**（3000 条随机对抗输入模糊测试覆盖）。
核心原则（开发方案 §8.4）：

- **接口不含标准答案**——识别与解析永不接触正确答案，杜绝偏向；
- 含修正语句（不对/错了/说错）、省略读法（三百二）、多个候选、混合格式时返回
  `Ambiguous`，要求重说，**绝不静默选择**；
- 无法解析（含语气词、非法语法）返回 `NotANumber`，**不判错**；
- 越界有效数字（如 56² 说成 99）正常判错，不当识别失败。

归一化：全角数字→半角、两→二、幺→一（电信读法，真机 ASR 实测会转写为汉字「幺」）。

## 3. 判题不变式（session.rs）

- 每次作答绑定 `(题目序号, 尝试ID)`；迟到结果（非当前题）拒收；
- 同一尝试 ID 幂等，判题计分至多一次；
- 未识别/歧义不计入算术错误；首答有效数字决定「首答正确率」，订正单独计数；
- SQLite 写通持久化，服务重启后 `resume()` 重建状态（含首答口径与已见尝试 ID）。

## 4. 墨水屏渲染：基线对齐 + 二值化

- 同行字形共享基线（fontdue 的 ymin/ymax 相对基线换算），中英混排不错位；
- 输出为纯 0/255 二值图（覆盖率 ≥ 64 落墨）：设备端 Floyd–Steinberg 抖色对二值图
  零噪声——灰阶抗锯齿在 16 灰屏上会形成明显脏边（实测教训）；
- 超宽文本自动缩字号（97×97 是最宽题面）。

## 5. ASR：子进程隔离 + 防偏向

- Rust 主程序通过 JSON-lines 与 Python worker 通信（背单词应用同模式）：
  模型崩溃不影响主程序，可重启；锁步请求 + 超时；
- worker 的系统提示词只描述任务形态，**不含任何标准答案或候选数字**；
- ASR 失败/超时只提示重说，不写入尝试记录（与「未识别」区分）。

## 6. 设备实测经验（docs/01 §3.2）

- 设备停在「设置/网络同步」页时远程画面不渲染，但协议照常 ACK → 应用启动引导
  退出设置页；
- 媒体音量为 0 时 `play` 返回 Completed 但无声 → 首用试音流程；
- 显示完成后 <3s 内再推返回 Busy → `show_retry` 退避重试；
- 客户端强杀后设备保活约 15s → 重连需退避；
- 服务模式：断线自动重连（10s 轮询）+ 当前画面自动恢复。

## 7. 与 vocabulary 应用的关系

架构范式（Rust 主程序 + Python 语音 worker、ASR 无提示词原则、按键交互）参考
[zectrix-vocabulary](https://github.com/itopinion/zectrix-vocabulary)（MIT）。
区别：本项目**不依赖 ZECTRIX Hub**，直接使用 zectrix-local-push-sdk 单机运行，
部署面更小；语音对象从英文字母/单词换为中文数字。
